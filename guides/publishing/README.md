# Publishing guides

How validated repository changes become a public release. This is separate from the behavior of an installed app receiving that release.

- [GitHub development and publishing](github-development-and-publishing.md) — side branches, PRs, authorized squash merges, production Actions and live verification.
- [TA PWA guide](../pwa/README.md) — app identities, icons, offline isolation and browser update prompts.
- [Repository conventions](../repositories/README.md) — project memory, logs and handovers.

Application-specific build commands, release cadence, staging directories and workflow exceptions stay in that application's repository. TA Guides itself remains a files-only collection with no website publishing workflow.
